# Week 8 - Day 1: Sprint 3 Planning & Diagnosing the N+1 Problem

## Day Overview

**Day 1 marked the kickoff of Sprint 3, shifting our focus from functionality to** **Performance Tuning**. The primary goal was to establish a measurable performance baseline and diagnose the **N+1 query problem**—a common bottleneck where a single request triggers redundant database round-trips.

## What We Learned

* **The N+1 Problem:** **How fetching a list (1 query) and then fetching related data inside a loop (N queries) leads to geometric performance degradation as data volume grows.**
* **EF Core Query Logging:** **Configuring** **.LogTo(Console.WriteLine)** **to expose the underlying SQL generated by Entity Framework.**
* **Measurable Benchmarking:** **Why performance improvements must be backed by "before and after" query counts rather than mere estimates.**
* **Realistic Data Seeding:** **The necessity of testing with a production-like volume (50+ records) to make performance issues visible.**

### Task 3: Seed Realistic Volume of Test Data

**To simulate a production scenario, we executed a SQL Stress Test script in** **SSMS** **to generate** **55 patients** **and** **165 vital sign records**, ensuring IDs start from a deterministic offset (ID 5 for patients).

**code**SQL

```
-- SSMS Script utilized to bypass Migration overhead for large datasets
WHILE @i <= 55
BEGIN
    INSERT INTO Patients (...) VALUES (...);
    SET @PatientId = SCOPE_IDENTITY();
    INSERT INTO VitalSigns (PatientId, ...) VALUES (@PatientId, ...);
END
```

### Task 4: Simulate and Confirm the N+1 Problem

**We implemented a deliberate "Bad Performance" endpoint that loads patients and then iterates through them to fetch vitals, triggering the N+1 behavior.**

**code**C#

```
// ⚠️ Inefficient N+1 Implementation
foreach (var patient in patients)
{
    // This triggers N additional database round-trips
    var vitals = await context.VitalSigns
        .Where(v => v.PatientId == patient.Id)
        .ToListAsync();
}
```

### Task 5: Document the Performance Bottleneck

**By running the** **test-n-plus-one** **endpoint and observing the terminal, we captured evidence of** **56 separate SELECT statements** **executed for a single HTTP request. This "Before" measurement serves as the baseline for our optimization tasks.**
