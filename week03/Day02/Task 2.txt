 Task 2 Submission: Database Normalization Analysis1. First Normal Form (1NF) – Atomic ValuesRule: Each column must contain atomic (indivisible) values, and there should be no repeating groups or arrays.Our Application:A member might have multiple phone numbers. Instead of storing multiple numbers in a single column separated by commas (e.g., "059123456, 056123456"), we extracted them into a separate table (MemberPhones).Every field across all tables (Authors, Books, Members, LendingRecords) holds exactly one single value per row.2. Second Normal Form (2NF) – Full Functional DependencyRule: The table must be in 1NF, and all non-key attributes must depend on the entire Primary Key (eliminating Partial Dependency).Our Application:All of our tables use a single-column Primary Key (Id).Since there are no composite primary keys, partial dependency is inherently impossible, and all columns depend completely on their respective table's Id.3. Third Normal Form (3NF) – Transitive DependencyRule: The table must be in 2NF, and non-key attributes must depend only on the Primary Key, not on other non-key attributes (eliminating Transitive Dependency).Our Application:Authors & Books: Instead of storing AuthorName or AuthorEmail inside the Books table, we moved author details to a separate Authors table. Storing author details in Books creates a transitive dependency (BookId $\rightarrow$ AuthorId $\rightarrow$ AuthorName).Members & LendingRecords: The LendingRecords table only references BookId and MemberId. It does not store MemberName or BookTitle, avoiding redundant data and transitive dependencies.
